    Lesson 10.2: array, deque, list, and forward_list¶

    C++20 · about 10 minutes

    Why this matters¶

    std::vector is the default, but not the only answer. A fixed-size table of filter coefficients doesn't need the heap at all (std::array). A queue that grows at both ends wants std::deque. And sometimes you genuinely need stable element addresses or O(1) splicing (std::list). Let's see when each one earns its place — and measure why lists usually don't.

    Container Layout Fast operations Iterators stable?
    array<T,N> inline, fixed everything; no heap yes (never reallocates)
    vector<T> contiguous heap block back insert/erase, random access until reallocation
    deque<T> blocks of elements front and back insert, random access references stable for end inserts; iterators not
    list<T> doubly linked nodes insert/erase anywhere given an iterator, splice yes
    forward_list<T> singly linked nodes same, less memory, forward only yes

    Big-O isn't everything¶

    Inserting in the middle of a list is O(1) — once you have the iterator. Finding the position is O(n) pointer chasing, with a likely cache miss per node. A vector insert is O(n) but it's a memmove of contiguous memory, which modern CPUs do extremely fast. The example times both (timings are printed for you to look at on your machine; they vary).

    examples/week10/lesson02.cpp
    #include <array>
#include <chrono>
#include <deque>
#include <forward_list>
#include <iostream>
#include <list>
#include <vector>

template <typename C>
long long insert_middle_ms(int n) {
    C c;
    auto t0 = std::chrono::steady_clock::now();
    for (int i = 0; i < n; ++i) {
        auto it = c.begin();
        std::advance(it, static_cast<long>(c.size() / 2));   // find the middle: O(n) either way
        c.insert(it, i);
    }
    auto t1 = std::chrono::steady_clock::now();
    return std::chrono::duration_cast<std::chrono::milliseconds>(t1 - t0).count();
}

int main() {
    constexpr auto coeffs = std::to_array({0.25f, 0.5f, 0.25f});   // no heap, size deduced
    static_assert(coeffs.size() == 3);

    std::deque<int> dq{2, 3};
    dq.push_front(1);
    dq.push_back(4);
    std::cout << "deque: " << dq.front() << ".." << dq.back() << " [2]=" << dq[2] << '\n';

    std::list<int> a{1, 2, 3}, b{10, 20};
    auto keep = a.begin();                                  // iterator to 1
    a.splice(std::next(a.begin()), b);                      // O(1): moves nodes, no copies
    std::cout << "list after splice: ";
    for (int x : a) std::cout << x << ' ';
    std::cout << "| b.size()=" << b.size() << " | iterator still valid: " << *keep << '\n';

    std::forward_list<int> fl{3, 2, 1};
    fl.push_front(4);
    fl.sort();
    std::cout << "forward_list sorted front: " << fl.front() << '\n';

    const int n = 20000;
    std::cout << "insert " << n << " in the middle (your timings will differ):\n";
    std::cout << "  vector: " << insert_middle_ms<std::vector<int>>(n) << " ms\n";
    std::cout << "  list:   " << insert_middle_ms<std::list<int>>(n) << " ms\n";
}

    Output (yours may differ: timing/threads):

    deque: 1..4 [2]=3
list after splice: 1 10 20 2 3 | b.size()=0 | iterator still valid: 1
forward_list sorted front: 1
insert 20000 in the middle (your timings will differ):
  vector: 2 ms
  list:   158 ms

    When list really wins¶

    • You need iterators/pointers to elements to stay valid while others are inserted/erased (e.g. an LRU cache: list + unordered_map of iterators).
    • You move ranges between lists with splice in O(1) without copying elements.
    • Elements are huge and non-movable.

    std::to_array (C++20) creates a std::array with the size deduced: auto a = std::to_array({1, 2, 3});.

    Key takeaways¶

    Key takeaways

    • std::array for fixed sizes (no heap); deque for both-end queues; vector for almost everything else.
    • Linked lists have O(1) insertion given an iterator but terrible cache behaviour; finding the position dominates.
    • Choose list for stable iterators and O(1) splice, not for 'fast insertion'.
    • Measure on your hardware — complexity classes hide constant factors.

    Quiz¶

    Q1. Why is vector typically faster than list at 'insert in the middle' for ints?

    Show answer

    Finding the middle is O(n) for both, but vector's traversal and shift are contiguous memory operations that are cache- and prefetch-friendly, while the list chases pointers with cache misses.

    Q2. What does splice do and why is it O(1)?

    Show answer

    It relinks nodes from one list into another without copying or allocating; only pointers change.

    Q3. Does std::array allocate on the heap?

    Show answer

    No — its elements are stored inline in the object (on the stack for a local).
